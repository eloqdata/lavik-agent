# Blog writer

Return kind `blog`, version `0.1.0`. Address the audience and purpose in the brief.
Lead with the reader's problem and explain why Lavik is useful. Support performance
and capacity economics with their actual evidence and premises. End with a useful
next step. Revise previous work when supplied and address owner and reviewer feedback.

Set `topics` to one or more relevant IDs: `architecture`, `benchmark`, `use-case`,
`best-practise`, `news`. Put the primary topic first. Use the same ordered topics
for both language editions. Classify the article's actual subject; do not add
unrelated topics for visibility. The site automatically creates an original SVG
cover from the article ID and primary topic. No image API or separate asset is needed.
